{%- comment -%} Cloudflare Web Analytics — replaces Google Analytics. Why: the previous GA property was Universal Analytics (UA-63935442-1). Google stopped processing UA data in July 2023, so it had collected nothing for years. Cloudflare Web Analytics is cookieless and sets no browser storage, so it does not require a consent banner and keeps the privacy policy simple. It works on sites that are NOT proxied through Cloudflare (ripeda.com is DNS-only at GoDaddy, pointing at GitHub Pages) via this manual beacon snippet. Setup: Cloudflare dashboard > Web Analytics > Add a site > enter ripeda.com > copy the token out of the JS snippet it gives you, and put it in _data/seo.yml as `cloudflare_analytics_token`. Only loads in production, so local `jekyll serve` never reports. CSP requirements (already in _layouts/default.html): script-src https://static.cloudflareinsights.com connect-src https://cloudflareinsights.com GOTCHA — do not guard this on a bare truthiness test of the token variable. Liquid only treats `nil` and `false` as falsy. An EMPTY STRING is TRUTHY. So with `cloudflare_analytics_token: ""` that guard passed and the beacon shipped to production as `data-cf-beacon='{"token": ""}'` — the script loaded on every page and reported nothing, while the config comment claimed nothing would load at all. That was live on ripeda.com from launch until 2026-07-30. Always compare against "" explicitly, as below. {%- endcomment -%} {%- assign cf_token = site.data.seo.cloudflare_analytics_token | default: "" | strip -%} {% if jekyll.environment == "production" and cf_token != "" %} {% endif %}
